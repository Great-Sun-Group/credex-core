Local CI/CD Pipeline Deployment Guide

This guide covers the new local deployment system that replaced the previous AWS-based infrastructure.

Overview

The local CI/CD pipeline automatically deploys services to the local production environment using GitHub Actions workflows that call deployment APIs running on the local server.

Architecture

Three Repository Structure

  • credex-core: Main API and backend services
  • vimbiso-chatserver: Chat/messaging service
  • vimbisopay: Flutter mobile application

Deployment Flow

GitHub Repository → GitHub Actions → Local Deployment API → Docker Compose Services

Deployment Endpoints

All deployment endpoints are hosted at http://localhost:4000 and require authentication via deployment token.

Service Deployment

  • POST /api/deploy-core - Deploy credex-core service
  • POST /api/deploy-chatserver - Deploy vimbiso-chatserver service

Mobile App Deployment

  • POST /api/upload-apk - Upload mobile app APK
  • GET /downloads/vimbisopay-{version}.apk - Download APK files

GitHub Actions Workflows

1. credex-core Repository

  • File: .github/workflows/deploy-local.yml
  • Trigger: Automatic on push to prod branch
  • Actions:
    • Checkout code
    • Call deployment API with service details
    • Verify deployment success
    • Report status and create artifacts

2. vimbiso-chatserver Repository

  • File: .github/workflows/deploy-local.yml
  • Trigger: Automatic on push to prod branch
  • Actions:
    • Checkout code
    • Call deployment API with service details
    • Verify deployment success
    • Report status and create artifacts

3. vimbisopay Repository

  • File: .github/workflows/deploy-mobile.yml
  • Trigger: Manual workflow dispatch
  • Actions:
    • Setup Flutter environment
    • Run tests and build APK
    • Auto-increment version based on update type
    • Upload APK to deployment API
    • Verify availability and commit version update

Version Management (Mobile App)

Version Increment Logic

  • Optional Update (update_required: false): Increment patch version
    • Example: 1.2.3 → 1.2.4
  • Required Update (update_required: true): Increment minor version, reset patch
    • Example: 1.2.3 → 1.3.0

Manual Deployment Process

  1. Navigate to vimbisopay repository on GitHub
  2. Go to Actions → Deploy Mobile App to Local Environment
  3. Click "Run workflow"
  4. Select update type (required/optional)
  5. Enter release notes
  6. Click "Run workflow" to start deployment

Security Configuration

Deployment Token Setup

  1. Generate a secure 32+ character token
  2. Add to GitHub repository secrets as DEPLOY_TOKEN
  3. Configure the same token in local environment variables
  4. All three repositories must have access to this secret

Required Secrets

Each repository needs the following GitHub secret:

  • DEPLOY_TOKEN: Secure deployment authentication token

Service URLs

Production Environment

  • Credex Core API: http://localhost:4000
  • API Documentation: http://localhost:4000/api-docs
  • Vimbiso ChatServer: http://localhost:9000
  • ChatServer Health: http://localhost:9000/health/

Mobile App Downloads

  • Versioned APK: http://localhost:4000/downloads/vimbisopay-{version}.apk
  • Latest APK: http://localhost:4000/downloads/vimbisopay-latest.apk

Troubleshooting

Common Issues

Deployment Authentication Failed

  • Cause: Invalid or missing deployment token
  • Solution: Verify DEPLOY_TOKEN secret is set correctly in repository settings

API Connection Failed

  • Cause: Local deployment API not running
  • Solution: Ensure credex-core production environment is running: 
    docker compose -f docker-compose.prod.yml up -d

Mobile App Build Failed

  • Cause: Flutter build errors or missing dependencies
  • Solution: Check workflow logs for specific Flutter errors

Version Increment Failed

  • Cause: Invalid version format in pubspec.yaml
  • Solution: Ensure version follows semantic versioning (x.y.z format)

Health Checks

Verify Deployment API

curl http://localhost:4000/api-docs

Verify ChatServer

curl http://localhost:9000/health/

Check Service Status

docker compose -f docker-compose.prod.yml ps

Monitoring

Deployment Artifacts

Each successful deployment creates artifacts containing:

  • Deployment metadata (timestamps, versions, actors)
  • Service configuration details
  • Download URLs (for mobile deployments)
  • APK files (for mobile deployments)

Logs

  • GitHub Actions: View workflow logs in repository Actions tab
  • Local Services: Use Docker logs to monitor service deployment 
    docker logs credex-core-prod --tail 50
docker logs vimbiso-chatserver-prod --tail 50

Migration from AWS

Archived Components

The previous AWS-based infrastructure has been archived:

  • Terraform configurations: Moved to archived_terraform/
  • AWS workflows: Moved to archived_terraform/workflows/
  • Documentation: Previous deployment docs preserved for reference

Key Changes

  • No cloud infrastructure: All services run locally
  • Direct deployment: No container registry or ECS deployments
  • Local file storage: APK files stored locally instead of S3
  • Simplified authentication: Single deployment token instead of AWS credentials

Best Practices

Development Workflow

  1. Develop and test changes locally
  2. Push to prod branch for automatic deployment (credex-core, vimbiso-chatserver)
  3. Use manual dispatch for mobile app deployments with appropriate update classification
  4. Monitor deployment logs and verify service health after deployment

Version Management

  • Use semantic versioning for all releases
  • Classify updates appropriately (required vs optional)
  • Include meaningful release notes for mobile deployments
  • Test deployments in development environment first

Security

  • Rotate deployment tokens regularly
  • Monitor deployment logs for unauthorized access attempts
  • Keep local production environment secure and updated
  • Use HTTPS in production (configure reverse proxy if needed)
