Account Types

The Vimbiso Market system uses different types of accounts to track various aspects of the marketplace. These accounts are divided into Exchange Accounts and Internal Accounts.

Exchange Accounts (neo4jNode:Account)

Exchange accounts exist in searchSpace and can close loops with other accounts. They represent current assets and current liabilities.

Type Description
PERSONAL • Created with membership (one per member, required)
• For purchase/sale transactions and gifts
OPERATIONS • Business accounts, shared accounts
• Created by Hustlers and above
• For purchase/sale transactions and gifts
TRUST • Audited bank or vault accounts
• Created and managed by Treasurers

Internal Accounts (neo4jNode:AccountInternal)

Internal accounts are created and managed by members but are not added to searchSpace and do not close loops with other accounts.

Type Description
CONSUMPTION • Used when an asset's value is consumed by a member
• Or within an economic process leading to consumption
PRODUCTION • Used when value is created or enhanced by a member
• Or within an economic process directed by members
DIGITAL_ASSET • Real asset whose complete value is stored digitally
• Can be duplicated without altering the original
• Value derived without altering the original
• Audit is redundant (data IS the asset)
PHYSICAL_ASSET • Digital representation of physical assets
• Cannot be duplicated without altering the original
• Value derived without altering the original
• Can be audited to confirm data matches physical assets

AssetMarker (neo4jNode:AssetMarker)

An AssetMarker is both an Asset and a General Ledger entry. This dual nature allows the system to track both the asset itself and its accounting relationships.

Dual Nature of AssetMarkers

As an Asset
  • Small assets (up to 2kb) stored directly on node
  • Larger assets reference S3 bucket data
  • S3 data accessed/decrypted using AssetMarker node data
As a General Ledger Entry
  • Connected to one or more accounts with CR (credit) relationships
  • Connected to one or more accounts with DR (debit) relationships
  • The sum of all CR relationships must equal the sum of all DR relationships

AssetMarker Relationships

GLid Field

AssetMarkers now include a GLid (General Ledger ID) field that groups related entries. This allows for simpler single CR/DR relationships while maintaining the ability to track related entries. 

(:AssetMarker {
  GLid: "shared-id",
  GeneralLedgerAmount: number,
  CXXmultiplier: number,
  Denomination: string
})

Invoice (neo4jNode::Invoice)

A credex template that directs the creation of the credex and associated accounting entries for the counterparties. Invoices are digitally signed by the creating member to ensure authenticity and non-repudiation. 

(:Invoice {
  invoiceID: string,                 // Unique Invoice ID
  Lines: string,                     // JSON array of line items (template)
  Amount: number,                    // Template amount
  Denomination: string,              // Currency denomination
  Notes: string,                     // Additional notes
  createdAt: datetime                // Creation timestamp
})-[:CREDITS_TO]->(:AccountInternal),

(:Invoice)<-[:EXECUTES]-(:Credex {
  GLid: string                       // Same GLid as related AssetMarkers
})

Invoice Flow

  1. Vendor creates an invoice specifying the product(s) and amount
  2. Vendor digitally signs the invoice using the system's signature mechanism
  3. System generates a QR code for the invoice
  4. Purchaser scans the QR code
  5. Purchaser creates a credex that executes the invoice
  6. System creates AssetMarkers with the same GLid as the Credex to represent the accounting entries
  7. The GLid field groups all related entries (Credex and AssetMarkers) for balance verification and aggregation

Digital Signatures

Invoices are digitally signed using the system's signature mechanism, which creates a (:Signature) node that links the member to the invoice. This provides a secure, auditable record of invoice creation. 

(:Member)-[:SIGNED]->(:Signature {
  signatureID: string,
  createdAt: datetime,
  actionType: "INVOICE_CREATED",
  inputData: string, // JSON string of invoice data
  requestId: string
})-[:SIGNED]->(:Invoice)

Market-Specific Invoice Features

In the Vimbiso Market context, invoices include additional features:

  • Product details including images, descriptions, and quantities
  • Vendor information and ratings
  • Delivery options and location information
  • Transaction history between the vendor and purchaser
