Client Implementation Workplan

A comprehensive guide for implementing client-side functionality for the Vimbiso Market.

Overview

This document provides detailed implementation guidelines for client-side developers working on the Vimbiso Market features. It focuses on key user flows and API interactions that need to be implemented in the client application.

Vendor Onboarding Process

The vendor onboarding process consists of two main steps:

  1. Enabling vendor functionality for a member
  2. Setting up the vendor profile with profile pictures

1. Enabling Vendor Functionality

To enable vendor functionality for a member, the client needs to call the /sellInMarket endpoint. This endpoint toggles the vendor status and creates the necessary internal accounts.

Implementation Steps:
  1. Add a toggle in the member profile UI to enable/disable vendor functionality.
  2. Call the /sellInMarket endpoint when the toggle is switched: 
    // Example implementation using axios
async function toggleVendorStatus(enabled) {
  try {
    const response = await api.post('/sellInMarket', {
      vendor: enabled
    });
    
    // Store the created account IDs for future use
    if (enabled && response.data.data.action.details.createdAccounts) {
      const createdAccounts = response.data.data.action.details.createdAccounts;
      
      // Find and store the account IDs
      const onboardedAssetsAccount = createdAccounts.find(
        account => account.accountName === "Onboarded Assets"
      );
      
      const profilePicturesAccount = createdAccounts.find(
        account => account.accountName === "Profile Pictures"
      );
      
      if (onboardedAssetsAccount && profilePicturesAccount) {
        // Store these IDs in your state management system
        // They will be needed for uploading profile pictures
        storeAccountIDs({
          onboardedAssetsAccountID: onboardedAssetsAccount.accountID,
          profilePicturesAccountID: profilePicturesAccount.accountID
        });
      }
    }
    
    return response.data;
  } catch (error) {
    console.error('Error toggling vendor status:', error);
    throw error;
  }
}
  3. Handle the response to update the UI and store the created account IDs.
  4. Show/hide vendor-specific UI elements based on the vendor status.
Key Considerations:
  • Account IDs Storage: The response from /sellInMarket includes the IDs of the created internal accounts. These IDs are crucial for future operations like uploading profile pictures and product images. They are now returned with the dashboard template.
  • Error Handling: Implement proper error handling to inform the user if the operation fails.
  • UI Feedback: Provide clear visual feedback during and after the operation.

2. Setting Up Vendor Profile Pictures

Setting up a vendor profile picture is a two-step process:

  1. Upload and optimize the image using /uploadAndOptimizeJpg
  2. Connect the image versions to the member profile using /connectMultipleAssets
Implementation Steps:
  1. Create a profile picture upload component in the vendor profile UI.
  2. Implement the image upload function to handle the first step: 
    // Example implementation using axios and FormData
async function uploadProfilePicture(imageFile) {
  try {
    // Create a FormData object to send the image
    const formData = new FormData();
    formData.append('jpg', imageFile);
    formData.append('name', 'profile_picture');
    formData.append('drAccountID', accountIDs.onboardedAssetsAccountID);
    formData.append('crAccountID', accountIDs.profilePicturesAccountID);
    
    const response = await api.post('/uploadAndOptimizeJpg', formData, {
      headers: {
        'Content-Type': 'multipart/form-data'
      }
    });
    
    // Extract the asset IDs from the response
    const { originalAssetID, asset200ID, asset600ID } = response.data.data.action.details;
    
    // Return the asset IDs for the next step
    return {
      originalAssetID,
      asset200ID,
      asset600ID
    };
  } catch (error) {
    console.error('Error uploading profile picture:', error);
    throw error;
  }
}
  3. Implement the connect assets function to handle the second step: 
    // Example implementation using axios
async function connectProfilePictures(assetIDs) {
  try {
    const { originalAssetID, asset200ID, asset600ID } = assetIDs;
    const memberID = currentUser.memberID;
    
    const response = await api.post('/connectMultipleAssets', {
  connections: [
    { connectedID: memberID, assetID: originalAssetID, relName: "PROFILE_PIC_ORIGINAL_JPG" },
    { connectedID: memberID, assetID: asset200ID, relName: "PROFILE_PIC_200_JPG" },
    { connectedID: memberID, assetID: asset600ID, relName: "PROFILE_PIC_600_JPG" }
  ]
    });
    
    return response.data;
  } catch (error) {
    console.error('Error connecting profile pictures:', error);
    throw error;
  }
}
  4. Combine both functions into a single user flow: 
    // Example implementation of the complete flow
async function setProfilePicture(imageFile) {
  try {
    // Show loading indicator
    setLoading(true);
    
    // Step 1: Upload and optimize the image
    const assetIDs = await uploadProfilePicture(imageFile);
    
    // Step 2: Connect the image versions to the member profile
    await connectProfilePictures(assetIDs);
    
    // Update UI to show the new profile picture
    // You can use the asset200ID for displaying the profile picture in the UI
    updateProfilePictureUI(assetIDs.asset200ID);
    
    // Show success message
    showSuccessMessage('Profile picture updated successfully');
  } catch (error) {
    // Show error message
    showErrorMessage('Failed to update profile picture');
  } finally {
    // Hide loading indicator
    setLoading(false);
  }
}
Key Considerations:
  • Image Size Limits: Implement client-side validation to ensure the image size is within acceptable limits.
  • Image Preview: Provide a preview of the image before uploading.
  • Progress Indication: Show upload progress to improve user experience.
  • Error Recovery: If the second step fails, provide a way to retry connecting the assets without re-uploading the image.
  • Caching: Cache the profile picture URLs to avoid unnecessary API calls.

Product Listing Process

The product listing process follows a similar pattern to the profile picture process, but with different relationship types.

1. Creating Product Accounts

Before listing products, vendors need to create internal accounts for each product category.

Implementation Steps:
  1. Create a product account creation UI in the vendor dashboard.
  2. Implement the account creation function: 
    // Example implementation using axios
async function createProductAccount(accountName) {
  try {
    const response = await api.post('/createAccountInternal', {
      accountName,
      defaultDenom: "USD",
      accountType: "PRODUCTION"
    });
    
    // Store the account ID for future use
    const accountID = response.data.data.action.details.accountID;
    
    return {
      accountID,
      accountName
    };
  } catch (error) {
    console.error('Error creating product account:', error);
    throw error;
  }
}

2. Uploading Product Images

The process for uploading product images is similar to profile pictures, but uses different relationship types.

Implementation Steps:
  1. Create a product image upload component in the product management UI.
  2. Implement the image upload function: 
    // Example implementation using axios and FormData
async function uploadProductImage(imageFile, productName, productAccountID) {

    formData.append('name', `${productName}_image`);

    formData.append('crAccountID', productAccountID);
    
    const response = await api.post('/uploadAndOptimizeJpg', formData, {
      headers: {
        'Content-Type': 'multipart/form-data'
      }
    });
    
    // Extract the asset IDs from the response
    const { originalAssetID, asset200ID, asset600ID } = response.data.data.action.details;
    
    // Return the asset IDs for the next step
    return {
      originalAssetID,
      asset200ID,
      asset600ID
    };
  } catch (error) {
    console.error('Error uploading product image:', error);
    throw error;
  }
}
  3. Implement the connect assets function: 
    // Example implementation using axios
async function connectProductImages(assetIDs, accountID) {
  try {
    const { originalAssetID, asset200ID, asset600ID } = assetIDs;
    
    const response = await api.post('/connectMultipleAssets', {
      connections: [
        { assetID: originalAssetID, connectedID: accountID, relName: "ACCOUNT_PIC_ORIGINAL_JPG" },
        { assetID: asset200ID, connectedID: accountID, relName: "ACCOUNT_PIC_200_JPG" },
        { assetID: asset600ID, connectedID: accountID, relName: "ACCOUNT_PIC_600_JPG" }
      ]
    });
    
    return response.data;
  } catch (error) {
    console.error('Error connecting product images:', error);
    throw error;
  }
}
Key Differences from Profile Pictures:
  • Relationship Types: Product images use ACCOUNT_PIC_* relationships instead of PROFILE_PIC_*.
  • Connected ID: Product images are connected to account IDs instead of member IDs.
  • Credit Account: Product images credit the product account instead of the profile pictures account.

Error Handling and Recovery

Proper error handling is crucial for a good user experience, especially in multi-step processes.

Error Handling Strategies

1. Validation Errors

Handle validation errors by providing clear feedback to the user: 

try {
  // API call
} catch (error) {
  if (error.response && error.response.status === 400) {
    // Extract validation errors from the response
    const validationErrors = error.response.data.errors;
    
    // Display specific error messages for each field
    Object.entries(validationErrors).forEach(([field, message]) => {
      showFieldError(field, message);
    });
  } else {
    // Handle other types of errors
    showGeneralError('An unexpected error occurred');
  }
}
2. Network Errors

Handle network errors by providing retry options: 

async function uploadWithRetry(fn, maxRetries = 3) {
  let retries = 0;
  
  while (retries < maxRetries) {
    try {
      return await fn();
    } catch (error) {
      retries++;
      
      if (error.isAxiosError && !error.response) {
        // Network error, wait before retrying
        await new Promise(resolve => setTimeout(resolve, 1000 * retries));
        
        if (retries < maxRetries) {
          // Show retry message
          showMessage(`Retrying... (${retries}/${maxRetries})`);
          continue;
        }
      }
      
      // If we get here, either it's not a network error or we've exhausted retries
      throw error;
    }
  }
}
3. Partial Success Handling

Handle cases where the first step succeeds but the second step fails: 

async function setProfilePictureWithRecovery(imageFile) {
  let assetIDs = null;
  
  try {
    // Step 1: Upload and optimize the image
    assetIDs = await uploadProfilePicture(imageFile);
    
    // Step 2: Connect the image versions to the member profile
    await connectProfilePictures(assetIDs);
    
    // Success case
    showSuccessMessage('Profile picture updated successfully');
    return true;
  } catch (error) {
    // Check if we have assetIDs (meaning step 1 succeeded)
    if (assetIDs) {
      // Step 1 succeeded but step 2 failed
      showErrorWithRetry(
        'Image uploaded but could not be connected to your profile',
        async () => {
          // Retry just the connection step
          await connectProfilePictures(assetIDs);
          showSuccessMessage('Profile picture updated successfully');
          return true;
        }
      );
    } else {
      // Step 1 failed
      showErrorMessage('Failed to upload profile picture');
    }
    
    return false;
  }
}

Performance Optimization

Optimize the client implementation for better performance and user experience.

Optimization Strategies

1. Image Compression

Compress images on the client side before uploading to reduce upload time: 

async function compressImage(file, maxSizeMB = 1) {
  // Use a library like browser-image-compression
  const options = {
    maxSizeMB,
    maxWidthOrHeight: 1920,
    useWebWorker: true
  };
  
  try {
    const compressedFile = await imageCompression(file, options);
    return compressedFile;
  } catch (error) {
    console.error('Error compressing image:', error);
    // Fall back to the original file
    return file;
  }
}
2. Caching

Cache account IDs and asset URLs to reduce API calls: 

// Example caching implementation
const cache = {
  accountIDs: null,
  assetURLs: {},
  
  // Set account IDs
  setAccountIDs(ids) {
    this.accountIDs = ids;
    // Persist to localStorage
    localStorage.setItem('accountIDs', JSON.stringify(ids));
  },
  
  // Get account IDs
  getAccountIDs() {
    if (!this.accountIDs) {
      // Try to load from localStorage
      const stored = localStorage.getItem('accountIDs');
      if (stored) {
        this.accountIDs = JSON.parse(stored);
      }
    }
    return this.accountIDs;
  },
  
  // Set asset URL
  setAssetURL(assetID, url) {
    this.assetURLs[assetID] = {
      url,
      timestamp: Date.now()
    };
  },
  
  // Get asset URL (with expiration)
  getAssetURL(assetID) {
    const cached = this.assetURLs[assetID];
    if (cached && Date.now() - cached.timestamp < 3600000) { // 1 hour expiration
      return cached.url;
    }
    return null;
  }
};
