Testing Against Deployed Environments

In addition to local testing, you can run tests against deployed environments to verify functionality in staging and development environments. This is useful for:

  • Verifying deployments
  • Testing against production-like configurations
  • Debugging environment-specific issues
  • Validating integrations with external services

Available Environments

To test against deployed environments, add the environment prefix to any test command:

  • Development: dev.mycredex.dev - prefix commands with dev
  • Staging: stage.mycredex.dev - prefix commands with stage

Running Tests Against Deployed Environments

Examples of testing against the development environment: 

# Run integration tests on dev
npm test dev integrate

# Run member tests on dev
npm test dev member

# Test endpoint on dev
npm test dev onboardmember Test Member1 1234567890 USD

# Reset dev environment
npm test dev clearforce

Examples of testing against the staging environment: 

# Run integration tests on staging
npm test stage integrate

# Run member tests on staging
npm test stage member

# Test endpoint on staging
npm test stage onboardmember Test Member1 1234567890 USD

# Reset staging environment
npm test stage clearforce

Environment-Specific Configurations

When testing against deployed environments, the test runner:

  • Sets NODE_ENV and API_ENV to the target environment
  • Runs tests with --runInBand to prevent concurrency issues
  • Uses the appropriate base URL for API requests
  • Skips starting a local server

The environment-specific flags are defined in tests/run.js: 

// Add environment-specific flags
const envFlags = {
  local: "",
  dev: "--runInBand",
  stage: "--runInBand",
};

Environment Variables

When testing against deployed environments, the following environment variables are set:

  • NODE_ENV: Set to the target environment (dev/stage)
  • API_ENV: Set to the target environment (dev/stage)
  • TEST_PARAMS: Contains the test parameters

Docker Container Testing

You can also run tests against deployed environments from within a Docker container: 

# Run tests against dev environment in container
npm run docker:test dev onboardmember Test Member1 1234567890 USD

# Run tests against staging environment in container
npm run docker:test stage onboardmember Test Member1 1234567890 USD

Best Practices for Deployed Environment Testing

When testing against deployed environments, follow these best practices:

  1. Use test accounts: Create dedicated test accounts with clear naming conventions
  2. Clean up after testing: Use clearforce or similar commands to reset the environment
  3. Be cautious with data: Avoid creating large amounts of test data in shared environments
  4. Coordinate with team: Communicate when running tests that might affect others
  5. Test in isolation: Use --runInBand to prevent concurrency issues (done automatically)
  6. Verify environment: Confirm you're testing against the intended environment

Troubleshooting

If you encounter issues when testing against deployed environments:

  • Connection issues: Verify network connectivity and VPN if required
  • Authentication failures: Check if your API key is valid for the environment
  • Unexpected behavior: Confirm the environment is running the expected version
  • Rate limiting: Add delays between requests or use rate limiter bypass keys if available
  • Data conflicts: Clear test data before running tests

For persistent issues, check the server logs or contact the environment administrator.
