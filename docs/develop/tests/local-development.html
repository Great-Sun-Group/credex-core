Local Development Testing

During local development, you can run tests either directly on your local machine or within a Docker container. The container approach is recommended when using the dev container environment as it ensures consistent test execution.

Test Runner Script

The tests/run.js script provides a unified interface for running tests. It handles:

  • Starting and stopping the test server
  • Parsing command-line arguments
  • Setting up the test environment
  • Running the appropriate tests
  • Passing parameters to tests via environment variables

Running Tests in Docker Container

To run tests in the Docker container environment: 

# Run all tests in container
npm run docker:test

# Run specific tests in container
npm run docker:test login
npm run docker:test member
npm run docker:test onboardmember Test Member1 1234567890 USD

Running tests in a container provides several benefits:

  • Consistent test environment across all developers
  • Isolation from local system dependencies
  • Matches the dev container environment configuration

Running Tests Locally

Alternatively, you can run tests directly on your local machine: 

# Run all tests
npm test

# Run all integration tests
npm test integrate

# Run all Member tests
npm test member

# Test a specific endpoint
npm test onboardmember Test Member1 1234567890 USD

# Reset test environment
npm test clearforce

# Run tests with coverage reporting
npm run test:coverage

Test Server Management

Note: The automatic server management described below has been replaced for now by a CLI-focused approach that uses existing Docker containers. The test runner no longer starts a new server but connects to an existing one. See the CLI-Focused Testing page for details.

The test runner automatically manages the test server:

  • Checks if a server is already running on port 3000
  • If no server is running, builds TypeScript and starts a test server
  • Waits for the server to initialize before running tests
  • Shuts down the server after tests complete (if it started the server)

This allows you to:

  • Run multiple tests in sequence without restarting the server
  • Start a server manually for debugging and still run tests against it
  • Ensure tests always have a server available

Test Parameters

Most tests accept parameters that are passed as command-line arguments: 

# Format: npm test [command] [param1] [param2] ...
npm test onboardmember John Doe 1234567890 USD
npm test login 1234567890
npm test createcredex eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9... 100 USD receiver-handle

The test runner:

  • Parses command-line arguments, handling quoted strings properly
  • Passes parameters to tests via the TEST_PARAMS environment variable
  • For tests requiring authentication, automatically runs login to get a JWT

Test Output

Tests provide detailed output to help with debugging and chaining tests:

  • Request and response details for each API call
  • Clear error messages when parameters are missing
  • Highlighted "DATA FOR NEXT STEP" sections with tokens, IDs, and other values needed for subsequent tests
  • Jest assertions to verify expected behavior

Test Environment

Note: The test environment setup has been simplified in the CLI-focused approach. The test setup no longer manages database connections directly or initializes server components. See the CLI-Focused Testing page for details on the current implementation.

The test environment is configured in tests/setup.ts:

  • Sets up environment variables for testing
  • Configures axios for API requests
  • Handles server initialization and cleanup
  • Ensures a daynode exists for testing
  • Manages database connections

Key environment variables for testing:

  • NODE_ENV=test: Forces test environment
  • DOCKER_ENV=true: Uses existing Docker container
  • JWT_SECRET=test-secret-key: Uses test JWT secret
  • CLIENT_API_KEY=love-achingly: Sets test API key
  • MINIMAL_LOGS=true: Enables minimal logging mode
