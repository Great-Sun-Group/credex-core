Adding Tests for New Endpoints

When adding a new API endpoint, you should create corresponding tests to ensure its functionality. This guide outlines the process for adding tests for new endpoints.

Test Structure Overview

The Credex testing architecture follows a two-file approach for each endpoint:

  1. Function File: A reusable function that encapsulates the API call logic
  2. Test File: A Jest test file that uses the function to test the endpoint

This separation allows the function to be reused in both individual endpoint tests and integration tests.

Step 1: Create the Function File

First, create a function file in tests/api/functions/ that encapsulates the API call logic: 

// tests/api/functions/newEndpoint.ts
import axios from "../../setup";

export async function newEndpoint(
  token: string,
  param1: string,
  param2: number,
  optionalParam?: string
) {
  const headers = {
    "x-client-api-key": process.env.CLIENT_API_KEY,
    "Authorization": `Bearer ${token}`
  };

  console.log(`\nCalling new endpoint with ${param1}...`);
  
  const requestBody = {
    param1,
    param2,
    ...(optionalParam && { optionalParam })
  };

  const response = await axios.post(
    "/newEndpoint",
    requestBody,
    { headers }
  );

  console.log("newEndpoint response:", JSON.stringify(response.data, null, 2));
  return response.data;
}

Key elements of a function file:

  • Import the configured axios instance from ../../setup
  • Export an async function with appropriate parameters
  • Set up headers with API key and authorization token
  • Log the request for debugging
  • Make the API request with appropriate method (GET, POST, etc.)
  • Log the response for debugging
  • Return the response data

Step 2: Create the Test File

Next, create a test file in tests/api/ that uses the function to test the endpoint: 

// tests/api/newEndpoint.test.ts
import axios from "../setup";

describe("newEndpoint Test", () => {
  it("tests the new endpoint functionality", async () => {
    const params = (process.env.TEST_PARAMS || "").split(" ").filter(Boolean);
    const [token, param1, param2, optionalParam] = params;

    if (!token || !param1 || !param2) {
      throw new Error(
        "Usage: npm test newEndpoint <token> <param1> <param2> [optionalParam]"
      );
    }

    const headers = {
      "x-client-api-key": process.env.CLIENT_API_KEY || "",
      "Authorization": `Bearer ${token}`
    };

    console.log("\nTesting new endpoint...");
    const response = await axios.post(
      "/newEndpoint",
      {
        param1,
        param2: parseFloat(param2),
        ...(optionalParam && { optionalParam })
      },
      { headers }
    );

    console.log(
      "newEndpoint response:",
      JSON.stringify(response.data, null, 2)
    );
    
    expect(response.status).toBe(200);
    expect(response.data.data.action.type).toBe("EXPECTED_ACTION_TYPE");
    
    // Print important information for the next step
    console.log("\n=== DATA FOR NEXT STEP ===");
    console.log(`Token: ${token}`);
    console.log(`Result ID: ${response.data.data.action.details.resultID}`);
    console.log("=========================\n");
  });
});

Key elements of a test file:

  • Import the configured axios instance from ../setup
  • Create a Jest test suite with describe and it
  • Parse parameters from process.env.TEST_PARAMS
  • Provide clear usage instructions for missing parameters
  • Make the API request and verify the response
  • Include assertions to validate the response
  • Print important information for subsequent tests

Step 4: Add Error Case Tests (if needed)

For comprehensive testing, add error case tests in tests/api/error-cases/: 

// tests/api/error-cases/newEndpoint.errors.ts
import axios from "../../setup";

describe("newEndpoint Error Cases", () => {
  it("handles invalid parameters", async () => {
    const params = (process.env.TEST_PARAMS || "").split(" ").filter(Boolean);
    const [token] = params;

    if (!token) {
      throw new Error("Error tests require a valid token");
    }

    const headers = {
      "x-client-api-key": process.env.CLIENT_API_KEY || "",
      "Authorization": `Bearer ${token}`
    };

    // Test missing required parameter
    try {
      await axios.post(
        "/newEndpoint",
        { param2: 123 }, // Missing param1
        { headers }
      );
      fail("Should have thrown an error for missing param1");
    } catch (error) {
      expect(error.response.status).toBe(400);
      expect(error.response.data.error.code).toBe("VALIDATION_ERROR");
    }

    // Test invalid parameter type
    try {
      await axios.post(
        "/newEndpoint",
        { 
          param1: "test",
          param2: "not-a-number" // Should be a number
        },
        { headers }
      );
      fail("Should have thrown an error for invalid param2 type");
    } catch (error) {
      expect(error.response.status).toBe(400);
      expect(error.response.data.error.code).toBe("VALIDATION_ERROR");
    }
  });
});

Best Practices for Test Implementation

  1. Clear Usage Instructions: Always include clear usage instructions in error messages
  2. Consistent Formatting: Follow the established patterns for logging and output
  3. Comprehensive Testing: Test both success and error cases
  4. Reusable Functions: Make functions reusable for integration tests
  5. Meaningful Assertions: Include assertions that verify the expected behavior
  6. Data for Next Step: Print important information for subsequent tests
  7. Parameter Validation: Validate and parse parameters appropriately
  8. Error Handling: Include proper error handling and logging

Example: Market Flow Test

For complex workflows, you can create a complete flow test like marketFlow.test.ts: 

// tests/api/marketFlow.test.ts
import { onboardMember } from "./functions/onboardMember";
import { sellInMarket } from "./functions/sellInMarket";
import { newEndpoint } from "./functions/newEndpoint";
// ... other imports ...

describe("Complete Flow with New Endpoint", () => {
  it("completes the full flow", async () => {
    // Step 1: Create test member
    console.log("\n--- Step 1: Create test member ---");
    const timestamp = Date.now();
    const memberResponse = await onboardMember(
      "Test",
      "Member",
      `${timestamp}`,
      "USD"
    );
    
    const token = memberResponse.data.action.details.token;
    
    // Step 2: Enable vendor functionality
    console.log("\n--- Step 2: Enable vendor functionality ---");
    await sellInMarket(token, true);
    
    // Step 3: Call new endpoint
    console.log("\n--- Step 3: Call new endpoint ---");
    const newEndpointResponse = await newEndpoint(
      token,
      "test-param",
      123
    );
    
    // ... continue with flow ...
    
    // Final verification
    expect(newEndpointResponse.data.action.type).toBe("EXPECTED_ACTION_TYPE");
  }, 60000); // 60 second timeout
});

This approach allows for testing complete workflows without manual intervention between steps.
