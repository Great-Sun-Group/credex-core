Application Deployment Workflow

This document provides an overview of the application deployment workflow, which is defined in .github/workflows/app.yml.

Prerequisites

Before running this workflow, ensure that:

  1. The connectors workflow has been run at least once for the target environment to create the necessary Terraform state infrastructure.
  2. The databases workflow has been run to create the Neo4j instances. The application will automatically use the bolt endpoints from Terraform state (no authentication required).
  3. All required secrets (JWT_SECRET, CLIENT_API_KEY, Firebase configuration, etc.) are properly configured in GitHub.

Workflow Overview

The workflow consists of one job:

  1. deploy_application: Builds and deploys the application to AWS ECS

Environment Configuration

The workflow determines the environment and related settings based on the Git branch:

Branch Environment Build Target Domain
prod production production mycredex.app
stage staging production stage.mycredex.dev
other development development dev.mycredex.dev

Application Deployment Process

1. Docker Image Build

The workflow builds a Docker image with environment-specific configuration:

  • Uses multi-stage builds with environment-specific targets
  • Includes build arguments for sensitive information:
    • NODE_ENV
    • Neo4j bolt URLs for local instances
    • JWT_SECRET
    • CLIENT_API_KEY
    • DEV_ADMIN_KEY
    • SKIP_RATE_LIMITER_KEY
    • OPEN_EXCHANGE_RATES_API
    • FIREBASE_PROJECT_ID
    • FIREBASE_CLIENT_EMAIL
    • FIREBASE_PRIVATE_KEY
  • Tags the image with the Git SHA
  • Pushes to environment-specific ECR repository

2. Infrastructure and Application Deployment

The deployment process uses a combination of Terraform and AWS CLI:

  • Terraform is used only to:
    • Initialize backend configuration
    • Read infrastructure outputs (Neo4j endpoints, etc.)
    • Note: Terraform apply is NOT used for app deployment
  • AWS CLI is used to:
    • Get current ECS task definition
    • Update task definition with new image and environment variables
    • Deploy updated task definition
    • Monitor deployment status and collect logs

3. ECS Deployment

Updates the ECS service with the new application version:

  • Fetches current task definition
  • Updates task definition with:
    • New Docker image
    • Environment variables from GitHub secrets
    • Node environment configuration
    • Firebase configuration for push notifications
    • Neo4j bolt URLs from Terraform outputs
    • WhatsApp configuration
    • Password pepper
  • Registers new task definition
  • Updates ECS service
  • Waits for service to stabilize (up to 40 attempts)

Verification System Infrastructure

1. AWS Resources

The verification system requires the following AWS resources:

  • S3 Bucket:
    • Name: credexbuckets4-verifybucket-photos-${environment}
    • Versioning enabled
    • Server-side encryption (AES-256)
    • Public access blocked
  • IAM Roles:
    • Rekognition service role
    • ECS task role with Rekognition permissions

2. Rekognition Setup

The Rekognition collection must be created via AWS SDK in the application code:

  • Collection ID: credex-member-faces-${environment}
  • Created during application initialization
  • Managed through IAM roles and policies

3. Security Configuration

The verification system includes the following security measures:

  • Encrypted storage for verification photos
  • Least privilege IAM roles
  • Private S3 bucket access
  • Secure API endpoints

State Management

The workflow uses the same state management infrastructure as the connectors workflow:

  • S3 Backend: credexbuckets4-statebucket-${ENVIRONMENT}
  • DynamoDB Lock Table: credexbuckets4-statebucket-lock-${ENVIRONMENT}

Infrastructure Outputs

The workflow outputs detailed information about the deployed application:

  • ECS Information:
    • Cluster ARN
    • Task Definition ARN
    • Service Name
    • Service ID
  • Deployment Details:
    • Environment
    • Docker Image URI
    • Build Target
  • Verification System:
    • S3 Bucket Name
    • Rekognition Role ARN

Security Considerations

  1. Secrets Management:
    • AWS credentials stored as GitHub secrets
    • Application secrets passed as build arguments
    • Environment variables set in ECS task definition
    • Firebase configuration securely managed through GitHub secrets
  2. Image Security:
    • Images stored in private ECR repository
    • Tagged with Git SHA for traceability
    • Built with no-cache option for fresh dependencies
  3. Verification System Security:
    • Encrypted storage for verification photos
    • Private S3 bucket access
    • Least privilege IAM roles

Troubleshooting

If deployment fails, check:

  1. Docker Build Issues:
    • Build logs for compilation errors
    • ECR push permissions
    • Build argument configuration
  2. ECS Deployment Issues:
    • Service events in AWS console
    • Container logs in CloudWatch
    • Task definition configuration
    • Failed task logs and reasons

Post-Deployment Verification

  1. Application Health:
    • Check ECS service status
    • Verify application health endpoint
    • Monitor application logs
    • Review deployment events and task status
  2. Verification System:
    • Verify S3 bucket configuration
    • Test Rekognition collection access
    • Validate IAM role permissions

Conclusion

The application deployment workflow provides a comprehensive solution for deploying the application. It ensures consistent deployments across environments through environment-specific configuration and state management. The workflow includes proper security measures, handles sensitive information appropriately, and provides detailed output for monitoring and troubleshooting. The deployment process, with proper infrastructure setup and application configuration, ensures that all components are updated together while maintaining proper dependencies.
