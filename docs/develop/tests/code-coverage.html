Code Coverage Overview

The project uses Jest's built-in code coverage reporting to track test coverage metrics. Code coverage helps identify untested code paths and ensures comprehensive test coverage across the codebase.

Running Tests with Coverage

To run tests with coverage reporting: 

# Run all tests with coverage
npm run test:coverage

This will:

  • Run all tests in the project
  • Generate a coverage report in the terminal
  • Create detailed HTML reports in the 'coverage' directory
  • Generate coverage files in various formats (lcov, clover)

Understanding Coverage Metrics

The coverage report includes four key metrics:

  • Statement Coverage: Percentage of program statements executed
  • Branch Coverage: Percentage of control structures (if statements, switches) executed
  • Function Coverage: Percentage of functions/methods called
  • Line Coverage: Percentage of executable lines of code run

Coverage Reports

After running tests with coverage, you can find:

  • Terminal output showing overall coverage statistics
  • Detailed HTML report at coverage/lcov-report/index.html
  • Machine-readable reports in the coverage directory (lcov.info, clover.xml)

The HTML report provides:

  • File-by-file coverage breakdown
  • Line-by-line coverage highlighting
  • Branch coverage visualization
  • Directory summaries

Coverage Configuration

Coverage settings are configured in jest.config.js: 

// jest.config.js
module.exports = {
  // ... other Jest configuration
  collectCoverageFrom: [
    "src/**/*.{js,ts}",
    "!src/**/*.d.ts",
    "!src/types/**",
    "!src/mocks/**",
    "!**/node_modules/**"
  ],
  coverageReporters: ["text", "lcov", "clover"],
  coverageDirectory: "coverage"
};

This configuration:

  • Excludes test files, type definitions, and other non-source files
  • Generates multiple report formats (text, lcov, clover)
  • Collects coverage from all JavaScript and TypeScript files under src/

Improving Coverage

To improve code coverage:

  1. Identify uncovered lines and branches in the coverage report
  2. Write additional tests targeting those specific code paths
  3. Focus on critical business logic and error handling paths
  4. Use Jest's .only and .skip modifiers to focus on specific tests during development
  5. Consider setting coverage thresholds in the Jest configuration to enforce minimum coverage levels

Coverage Thresholds

You can set coverage thresholds in jest.config.js to enforce minimum coverage levels: 

// jest.config.js
module.exports = {
  // ... other Jest configuration
  coverageThreshold: {
    global: {
      statements: 80,
      branches: 70,
      functions: 80,
      lines: 80
    },
    "src/api/**/*.ts": {
      statements: 90,
      branches: 80,
      functions: 90,
      lines: 90
    }
  }
};

With this configuration, tests will fail if coverage drops below the specified thresholds.
