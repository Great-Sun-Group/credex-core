Architecture

The DeepSeek deployment uses a hybrid architecture that combines:

  • SageMaker Serverless Inference for hosting the DeepSeek model
  • Proxy Service running on existing EC2 instances for request management and caching

This architecture provides several benefits:

  • Cost efficiency through serverless scaling (pay only for compute time used)
  • Request caching to reduce duplicate requests
  • Minimal impact on existing infrastructure
  • Simplified integration with the Cline VS Code extension

Infrastructure Components

1. SageMaker Serverless Module

The SageMaker Serverless module (terraform/modules/sagemaker-serverless) manages the deployment of the DeepSeek model to AWS SageMaker Serverless Inference. Key components include:

  • IAM Roles and Policies for SageMaker execution
  • SageMaker Model configuration
  • Serverless Endpoint Configuration with memory and concurrency settings
  • SageMaker Endpoint deployment

2. Proxy Service

The proxy service (terraform/files/deepseek-proxy) is a Node.js application that:

  • Handles requests from the Cline VS Code extension
  • Implements request caching using Redis
  • Forwards requests to the SageMaker endpoint
  • Manages error handling and retries
  • Provides batch processing capabilities

3. IAM Permissions

The deployment requires specific IAM permissions defined in terraform/iam_sagemaker.tf:

  • Permission to invoke SageMaker endpoints
  • Permission to describe endpoints for status checking

Deployment Process

Step 1: Deploy SageMaker Serverless Infrastructure

The first step is to deploy the SageMaker Serverless infrastructure using Terraform: 


# Initialize Terraform
cd terraform
terraform init

# Plan the deployment
terraform plan -target=module.deepseek_serverless

# Apply the changes
terraform apply -target=module.deepseek_serverless

This will create:

  • IAM roles and policies for SageMaker
  • SageMaker model configuration
  • Serverless endpoint configuration
  • SageMaker endpoint

Step 2: Deploy Proxy Service

The proxy service is deployed to existing EC2 instances using Docker Compose: 


# Copy the proxy service files to the EC2 instance
scp -r terraform/files/deepseek-proxy user@ec2-instance:/path/to/deploy

# SSH into the EC2 instance
ssh user@ec2-instance

# Set the environment variable for the current environment
export ENVIRONMENT=development

# Start the service
cd /path/to/deploy/deepseek-proxy
docker-compose up -d

Step 3: Configure Cline Extension

Configure the Cline VS Code extension to use the proxy service:

  1. API Endpoint URL: Set the API endpoint to your domain with the appropriate path: 
    https://[your-domain]/api/deepseek/completion

    For example:

    • Development: https://dev.mycredex.dev/api/deepseek/completion
    • Staging: https://stage.mycredex.dev/api/deepseek/completion
    • Production: https://mycredex.app/api/deepseek/completion
  2. API Key Authentication: Include the x-api-key header with your DeepSeek API key: 
    x-api-key: your-deepseek-api-key

    This API key is stored as a secret in your GitHub repository and injected into the proxy service during deployment.

Configuration Options

SageMaker Serverless Configuration

The SageMaker Serverless endpoint can be configured with the following parameters:

Parameter Description Default Value
memory_size_in_mb Memory allocation for the serverless endpoint (supported values: 1024, 2048, 3072, 4096, 5120, 6144) 6144 (6GB)
max_concurrency Maximum number of concurrent invocations 5
container_image Docker image for the model HuggingFace PyTorch Inference
model_data_url S3 URL for the model data s3://deepseek-model-${environment}/deepseek-coder-6.7b/model.tar.gz

Proxy Service Configuration

The proxy service can be configured with the following environment variables:

Variable Description Default Value
PORT Port for the proxy service 3001
AWS_REGION AWS region for SageMaker af-south-1
SAGEMAKER_ENDPOINT Name of the SageMaker endpoint deepseek-serverless-${ENVIRONMENT}
DEEPSEEK_API_KEY API key for authenticating requests to the proxy service No default (must be provided)
AWS_ACCESS_KEY_ID AWS access key for SageMaker API access No default (must be provided)
AWS_SECRET_ACCESS_KEY AWS secret key for SageMaker API access No default (must be provided)

Cost Estimation

For two developers working 30-70 hours of coding per week, the estimated monthly costs are:

SageMaker Serverless Costs

  • Active hours: 50 hours/week = 215 hours/month
  • Requests per hour: ~100 requests/hour
  • Total requests: 21,500 requests/month
  • Memory configuration: 6GB
  • Average processing time: ~5 seconds per request
  • Compute duration: 21,500 requests × 5 seconds × 6GB × $0.0000185 = $11.93/month

Additional Costs

  • EC2 resource usage: Negligible (using existing infrastructure)
  • Redis cache: ~$5-10/month (if not already using Redis)
  • Data transfer: ~$20-40/month
  • S3 storage for model artifacts: ~$5-10/month

Monitoring and Maintenance

Monitoring

Monitor the deployment using:

  • CloudWatch Metrics for SageMaker endpoint performance
  • Docker logs for the proxy service
  • Redis monitoring for cache performance

Maintenance

Regular maintenance tasks include:

  • Updating the DeepSeek model as new versions are released
  • Optimizing cache settings based on usage patterns
  • Adjusting serverless configuration based on performance metrics
  • Monitoring costs and optimizing as needed

Troubleshooting

Common Issues

  • Cold Start Latency
    • Symptom: First request after inactivity is slow
    • Solution: Implement a warming strategy or adjust client-side timeout settings
  • Connection Issues
    • Symptom: Proxy service cannot connect to SageMaker endpoint
    • Solution: Check IAM permissions and network configuration
  • Cache Issues
    • Symptom: Cache not working or high miss rate
    • Solution: Check Redis connection and cache key generation
  • Authentication Issues
    • Symptom: Receiving 401 Unauthorized responses
    • Solution: Verify the API key is correctly set in both the client request headers and the proxy service environment variables
  • AWS Credentials Issues
    • Symptom: Proxy service cannot invoke SageMaker endpoint
    • Solution: Ensure AWS credentials are correctly set in the environment variables
  • Memory Size Limitations
    • Symptom: Deployment fails with memory size error
    • Solution: Ensure memory_size_in_mb is set to one of the supported values (1024, 2048, 3072, 4096, 5120, 6144)

Logs and Diagnostics

Access logs and diagnostics information: 


# View proxy service logs
docker-compose logs -f

# Check SageMaker endpoint status
aws sagemaker describe-endpoint --endpoint-name deepseek-serverless-${ENVIRONMENT}

# Monitor CloudWatch metrics
aws cloudwatch get-metric-statistics --namespace AWS/SageMaker --metric-name Invocations --dimensions Name=EndpointName,Value=deepseek-serverless-${ENVIRONMENT}

Conclusion

The hybrid approach with SageMaker Serverless and a proxy service provides a cost-effective and scalable solution for deploying DeepSeek for developer use. By leveraging serverless infrastructure and implementing efficient caching, the solution minimizes costs while providing good performance for the Cline VS Code extension.
