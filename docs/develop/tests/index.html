Test Architecture

The Credex test suite is organized into three main categories:

  • Endpoint Tests: Individual API endpoint tests that can be run in isolation or as part of larger flows
  • Integration Tests: End-to-end scenarios testing multiple endpoints in sequence
  • DevAdmin Operations: Administrative commands for test environment setup

Tests are structured in the following directories: 

tests/
├── api/                  # API endpoint tests
│   ├── functions/        # Reusable endpoint functions
│   ├── error-cases/      # Error case tests
│   ├── devadmin/         # DevAdmin operation tests
│   └── Member/           # Member-specific tests
├── integration/          # Integration test scenarios
├── noti_cache/           # Notification tests
├── utils/                # Test utilities
│   ├── cleanup.ts        # Test data cleanup
│   ├── setup-test-data.ts # Test data setup
│   ├── testUtils.ts      # General test utilities
│   └── endpoints/        # Endpoint-specific utilities
├── run.js                # Test runner script
└── setup.ts              # Global test setup

Test Types

Endpoint Tests

Each API endpoint has a dedicated test file in the tests/api/ directory that:

  • Tests a specific endpoint with appropriate parameters
  • Verifies response structure and status codes
  • Handles authentication when needed
  • Provides clear usage instructions
  • Outputs data needed for subsequent tests

Function Files

Common endpoint functionality is encapsulated in reusable functions under tests/api/functions/:

  • Provide consistent interfaces for API operations
  • Handle request formatting and response parsing
  • Include proper error handling
  • Support both individual tests and integration flows

Integration Tests

Integration tests in tests/integration/ verify complete workflows:

  • Test end-to-end scenarios across multiple endpoints
  • Verify data consistency throughout the flow
  • Test complex business logic spanning multiple operations
  • Validate system behavior in realistic usage scenarios

Error Case Tests

Error case tests in tests/api/error-cases/ verify proper error handling:

  • Test validation errors with invalid inputs
  • Verify appropriate error codes and messages
  • Test authorization and authentication failures
  • Ensure robust error handling throughout the API

Notification Tests

Notification tests in tests/noti_cache/ verify the notification system:

  • Test FCM token management
  • Verify notification sending for various events
  • Test notification content and formatting
  • Validate error handling in the notification pipeline

Market Tests

The Vimbiso Market functionality has dedicated tests that:

  • Test vendor profile management
  • Verify product listing and inventory management
  • Test invoice generation and payment processing
  • Support both step-by-step testing and complete flows

Test Runner

The tests/run.js script provides a command-line interface for running tests:

  • Supports running individual endpoint tests
  • Handles environment selection (local, dev, stage)
  • Manages server startup and shutdown
  • Passes parameters to tests via environment variables
  • Supports special test types (integration, error cases, etc.)

For detailed information on running tests, see the Local Development Testing and Command Reference pages.
