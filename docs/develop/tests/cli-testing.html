CLI-Focused Testing Approach

The Credex testing infrastructure has been optimized for a CLI-focused approach that prioritizes:

  • Simplicity and directness in test execution
  • Minimal output focused on essential information
  • Using existing Docker containers instead of creating new ones
  • Clear separation between test code and server code
  • Efficient testing workflows for developers

Using Existing Docker Containers

A key improvement in our testing approach is the ability to use existing Docker containers instead of creating new ones for each test. This provides several benefits:

  • Faster test execution by eliminating container startup time
  • Reduced resource usage on development machines
  • Ability to test against a consistent environment
  • Prevention of port conflicts and other container-related issues
  • More realistic testing against a long-running server

To use this approach: 

# First, start your development Docker container
npm run docker:dev

# In another terminal, run tests using the existing container
npm test onboardmember John Doe 1234567890 USD

The test runner automatically detects the running Docker container and uses it instead of starting a new one.

Minimal Output Mode

Tests now support a minimal output mode that focuses on essential information:

  • Shows only the most important test data
  • Eliminates verbose logging from the server
  • Suppresses coverage reports unless explicitly requested
  • Provides clear success/failure indicators
  • Displays the complete API response data for inspection

Clean Separation of Test and Server Code

The updated testing infrastructure maintains a clean separation between test code and server code:

  • Tests do not import server code directly
  • Tests communicate with the server only through the API
  • No shared state between tests and server
  • Tests run in a separate process from the server
  • Server configuration is not modified by tests

This separation ensures that tests are testing the actual API as it would be used by clients, not internal implementation details.

Implementation Details

Test Runner (tests/run.js)

The test runner has been updated to:

  • Set DOCKER_ENV=true to use existing Docker containers
  • Set MINIMAL_LOGS=true to enable minimal output mode
  • Disable coverage reports by default with --no-coverage
  • Remove silent mode to show console.log output from tests
  • Set environment variables to disable server logging

Test Setup (tests/setup.ts)

The test setup has been simplified to:

  • Remove all server code imports
  • Use a minimal logger for test output
  • Connect to the existing server without starting a new one
  • Set essential environment variables only
  • Remove database cleanup that's not needed with Docker containers

Test Files (tests/api/*.test.ts)

Test files have been updated to:

  • Print complete API response data
  • Focus on essential information in logs
  • Maintain compatibility with the existing test runner
  • Support both minimal and verbose output modes

Best Practices for CLI-Focused Testing

  1. Start Docker First: Always start your Docker container with npm run docker:dev before running tests
  2. Use Unique Identifiers: Use unique phone numbers or identifiers to avoid conflicts
  3. Examine Complete Response: Review the complete API response to understand the data structure
  4. Chain Commands: Use the output from one test as input to the next
  5. Keep Docker Running: Maintain a long-running Docker container for multiple test sessions
  6. Reset When Needed: Use npm test clearforce to reset the environment when needed

Example Workflow

A typical workflow using the CLI-focused approach: 

# Start Docker container
npm run docker:dev

# In another terminal, onboard a new member
npm test onboardmember John Doe 9876543210 USD
# Copy the token from the output

# Use the token to create an account
npm test createAccountInternal eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9... "Business Account" USD BUSINESS
# Copy the account ID from the output

# Use the token and account ID for further operations
npm test addAssetMarker eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9... "Test Asset" account-id-1 100 account-id-2 100 USD
